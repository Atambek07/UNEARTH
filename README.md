# UNEARTH — Smart LFG-to-Energy & Computational Grid Simulator (MVP)

B2B/G2G платформа для Бишкекского санитарного полигона: моделирует добычу
свалочного газа (метана) из 20 млн т «старого тела» свалки, конверсию в
электроэнергию (off-grid, газопоршневые Jenbacher) и питание модульных
дата-центров (ИИ-серверы / Antminer S19 Pro) прямо на полигоне.

```
Старый мусор → Подземный метан → Электричество → Вычисления (ИИ / Майнинг)
                                    └──────────→ Green Tracker (CO₂, деревья)
```

## Запуск

### Backend (FastAPI + ML)

```powershell
cd D:\UNEARTH\backend
py -m pip install -r requirements.txt
py -m uvicorn app.main:app --reload --port 8000
```

- Swagger: http://localhost:8000/docs
- Проверка: `GET http://localhost:8000/api/health`
- Тесты: `python -m pytest tests -q`

### Frontend (React + Vite + Tailwind)

```powershell
cd D:\UNEARTH\frontend
npm install
npm run dev            # http://localhost:5173, /api проксируется на :8000
npm run build          # прод-сборка (tsc strict + vite build)
```

Порядок работы дашборда: страница сама запускает симуляцию дефолтами Бишкека;
кнопка «Запустить симуляцию» повторяет прогон с текущими параметрами.

## Модули

### Модуль 1 — ML-ядро прогнозирования (`/api/forecast`)

1. **Физика (LandGEM, EPA)**: `Q(t) = Σ k·L0·Mi·exp(-k·age)` по когортам.
   Входы: 20 млн т накопленных ТБО (равномерно за 54 года, с 1972), приток
   350–400 тыс. т/год (стационарный вклад ≈ L0·M/12 в месяц), L0 = 70–80 м³/т,
   k = 0.02–0.04 1/год, 1 м³ CH₄ ≈ 3.5 кВт·ч эл. × отбор газа × готовность ГПУ.
2. **ML-сезонность (гибрид)**: поверх физической кривой строится «история
   наблюдений» (48 мес, seed), из неё MA-12-декомпозицией извлекаются
   эмпирические сезонные индексы и AR(1)-остатки; прогноз =
   физтренд × сезонный индекс × AR-продолжение, интервалы — 95 % CI из σ
   инноваций с ростом по горизонту. Осенний пик влажности (арбузы, дыни)
   задан явно: +18 % к генерации в сентябре–октябре и ×2.3 к волатильности.
   Если установлен пакет `prophet` и в запросе `use_prophet: true` — прогноз
   делает Prophet (годовая сезонность + мультипликативный регрессор физтренда);
   при любой ошибке — автоматический откат на встроенную модель.

### Модуль 2 — Smart Grid и обслуживание

1. **Балансировщик (`/api/optimize`)**: derate мощности по качеству газа
   (CH₄ < 40 % — срывы горения, H₂S > 50 ppm — ограничение), маржа на кВт·день
   по классам узлов (майнинг: доход сети BTC × ML-множитель прогноза − амортизация
   1.75 ¢/кВт·ч; ИИ: рента GPU × 24 ч − та же амортизация), жадное заполнение
   по убыванию маржи с рыночным ограничением спроса на GPU (1000 GPU).
   При падении мощности/качества — лестница отключений по возрастанию маржи
   (первыми отключаются майнеры). «Manual Allocation» считает экономику
   заданного пользователем парка и флаг перегруза.
2. **Обслуживание (`/api/maintenance`)**: износ ГПУ, %/мес =
   0.35·(H₂S/25)^1.35; health, RUL, риск отказа за 12 мес по каждому
   Jenbacher; ресурс скрубберов = ёмкость сорбента / загрузка серы
   (расход LFG × ppm × плотность H₂S); замены → OPEX; резерв капремонтов —
   по вероятностной оценке.

### Модуль 2в — Финансы и Green Tracker (`/api/finance`)

CAPEX по статьям (скважины, ГПУ 750 $/кВт, скрубберы, ЦОД-контейнеры, железо
вычислений, резерв 12 %), Монте-Карло (400 траекторий BTC GBM + крэши и рост
сложности сети, рента GPU OU) → P10/P50/P90 выручки и прибыли, дисконтированный
кумулятивный поток (WACC 10 %), окупаемость и IRR. CO₂-эквивалент = уничтоженный
CH₄ × GWP-28; Фонд озеленения = 5 % чистой прибыли → саженцы.

### Карта секторов (`/api/sectors`)

48 секторов (6×8): возрастные классы (свежие/средние/старые), поток газа по
долям массы (Dirichlet), H₂S по классам с осенней поправкой; статус —
`green` / `amber` / `red` (высокий H₂S или RF-прогноз нестабильности > 0.7) /
`depleted` (выработан).

## REST API

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET  | `/api/health` | статус, доступность Prophet |
| POST | `/api/forecast` | LandGEM + ML-прогноз (годовой и месячный ряды, CI) |
| POST | `/api/optimize` | Smart Grid: авто или ручное распределение |
| POST | `/api/maintenance` | износ ГПУ, скрубберы, OPEX |
| POST | `/api/finance` | Монте-Карло, окупаемость, CO₂, Фонд озеленения |
| POST | `/api/sectors` | карта секторов |
| POST | `/api/simulation/run` | сквозной прогон всех модулей одним запросом |

Все эндпоинты описаны в Swagger (`/docs`); входные модели — `backend/app/schemas.py`,
зеркало для фронтенда — `frontend/src/types.ts`.

## Константы и допущения

Все «физические» числа — из проектного досье UNEARTH (ЕБРР/Мэрия/EPA): 20 млн т,
350–400 тыс. т/год, L0 70–80 м³/т, k 0.02–0.04, CH₄ 50–55 %, 3.5 кВт·ч/м³,
Antminer S19 Pro 3.25 кВт, ИИ-сервер 1.5 кВт, амортизация 1.5–2 ¢/кВт·ч.
Экономические параметры (цены CAPEX, GWP-28, рента GPU 2 $/GPU·ч, курс BTC
65 000 $ и т.п.) — помечены `ASSUMPTION` в `backend/app/config.py` и
переопределяются через параметры API.

## Известные ограничения MVP

- Рыночные данные синтетические (GBM/OU с фиксированным seed) — по ТЗ;
  для боевой версии подключается реальный лента цен.
- Prophet — опциональная зависимость (тяжёлый cmdstan-тулчейн); встроенная
  модель сезонности полностью реализована и работает без него.
- Налоги и тарифы КР не моделируются (pretax); выручка считается в USD.
- Симуляционные данные, не инвестиционная рекомендация.
